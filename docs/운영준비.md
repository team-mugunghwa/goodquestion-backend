# 서비스 운영 준비

> **목적**: 기능이 도는 상태와 사람이 실제로 쓸 수 있는 상태 사이의 간격을 적는다.
> 무엇이 비어 있고, 왜 그것이 문제이며, 어디를 고치면 되는지를 한 곳에 모은다.
>
> 엔드포인트 구현 현황은 [API-DTO.md 7절](API-DTO.md)이 원본이다. 이 문서는 기능
> 목록이 아니라 **기능 바깥의 것**을 다룬다.

---

## 0. 이 문서가 다루는 것

"고도화"라고 부르지 않는다. 고도화는 잘 돌아가는 것을 더 낫게 만든다는 뜻인데,
여기 적힌 상당수는 아직 없거나 안 되는 것을 채우는 일이다. 외부 API 타임아웃이 없고
로그아웃이 실제로는 세션을 못 끊는 것은 개선 대상이 아니라 미비점이다.

정확한 이름은 **운영 준비**이고, 표준 용어로는 **비기능 요구사항**이다. 성능, 안정성,
보안, 운영성처럼 "무엇을 하는가"가 아니라 "어떻게 버티는가"에 해당하는 것들이다.

다섯 묶음으로 나뉜다.

| 묶음 | 한 줄 설명 |
| --- | --- |
| 안정성 | 외부 API가 느려지거나 죽어도 서비스가 멈추지 않는다 |
| 성능과 확장성 | 같은 서버로 더 많은 아이를 받는다 |
| 보안과 개인정보 | 아동 정보를 다루는 서비스의 최소선을 맞춘다 |
| 운영과 관측 | 문제가 생겼을 때 사용자보다 우리가 먼저 안다 |
| 정합성 | 동시 요청에도 상태와 잔액이 어긋나지 않는다 (완료) |

---

## 1. 왜 지금인가

세 가지가 겹쳐 있다.

**하나.** 대화 턴이 붙는 순간 이 서비스는 외부 API에 크게 기댄다. 발화 1건에 LLM을
2번 부르고 STT와 TTS가 따로 붙는다. 지금 코드에는 그 호출에 타임아웃이 없다.

**둘.** 아이 발화 원문과 사고 특성 평가를 저장한다. 보호자 계정 하나가 그 기록 전체의
열쇠인데 로그아웃이 실제로는 토큰을 회수하지 못한다.

**셋.** `develop`에 push하면 곧바로 재배포된다. 테스트를 거치지 않고, 진행 중이던
요청은 끊기며, 죽어도 알림이 없다.

---

## 2. 해야 할 것

예상 시간은 앞이 직접 짤 때, 뒤가 AI를 쓸 때다. 결정과 외부 계정 설정, 실제 확인이
대부분인 항목은 두 값이 같다.

| # | 항목 | 왜 중요한가 | 어디에, 권장값 | 시간(직접/AI) |
| --- | --- | --- | --- | --- |
| 1 | 외부 호출 타임아웃 | 발화 1건에 LLM을 2번 부른다. 벤더가 30초씩 매달리면 동시 발화 몇십 건으로 요청 스레드가 마르고, 그때부터 로그인조차 안 된다 | `WebClientConfig` (지금 TODO만). 응답 10초, 연결 3초, 재시도 1회 | 30분 / 20분 |
| 2 | LLM 실패 폴백 | 타임아웃을 걸면 그다음은 아이 화면에 무엇이 뜨느냐다. 빈 화면이면 놀이가 거기서 끊기고 아이는 이유를 모른다 | `CharacterResponseService`. 실패 시 "잠깐만, 생각 좀 해볼게" 같은 고정 대사 | 1시간 / 30분 |
| 3 | 멀티파트 한도 | 30초 16kHz mono WAV가 약 960KB인데 Boot 기본이 1MB다. 아이가 32초만 말해도 413이 뜨는데 서버 로그에는 원인이 안 남는다 | `application.yml`. `max-file-size: 10MB` | 10분 / 10분 |
| 4 | Graceful shutdown | push마다 재배포된다. 지금은 처리 중이던 요청이 끊겨 아이 발화만 저장되고 캐릭터 대사는 없는 반쪽 상태가 남는다 | `server.shutdown: graceful` | 5분 / 5분 |
| 5 | 가상 스레드 | 요청 시간의 대부분이 STT/LLM/TTS 대기다. 스레드가 대기에 묶이지 않으면 같은 서버로 감당하는 동시 사용자 수가 몇 배가 된다. JDK 25라 `synchronized` 고정 문제도 없다 | `spring.threads.virtual.enabled: true` | 10분 / 10분 |

| 7 | 비동기 스레드풀 | 기본 `SimpleAsyncTaskExecutor`는 작업마다 스레드를 만들고 상한이 없다. 리포트 생성이 붙어 있어 동시 완주가 몰리면 무제한으로 늘어난다 | `AsyncConfig`. core 2, max 8, queue 100 | 30분 / 10분 |
| 8 | CI 게이트 | push가 곧 배포인데 테스트를 안 돌린다. 심사 전날 깨진 커밋 하나가 그대로 운영에 나간다 | GitHub Actions에 `./gradlew test` | 30분 / 15분 |
| 9 | 서비스 외부 감시 | 앱이 죽으면 에러 추적도 신호를 못 보낸다. 죽었다는 사실 자체를 알려주는 건 밖에서 두드리는 것뿐이다 | `/actuator/health`를 5분 간격 외부 감시 | 10분 / 10분 |
| 10 | 해금 기준 조정 | 이야기 1편에서 얻는 별가루 상한이 6인데 토끼는 30, 거북이는 50에 열린다. 상점 절반이 영원히 실루엣이다 | `R__1_seed_content.sql`의 `unlock_stardust_total` | 10분 / 10분 |

## 3. 이미 되어 있는 것

눈에 보이지 않는 작업이라 적어 두지 않으면 아무도 모른다. 여기에 시간을 더 쓰지 않는다.

| 항목 | 무엇을 막는가 | 어디에 |
| --- | --- | --- |
| 낙관적 락 | 한 턴 처리가 수 초 걸려 아이가 연타하면 턴 카운터와 누적 요소가 덮인다. 덮어쓰기 대신 충돌로 드러내 409로 바꾼다 | `StorySession.version` |
| 비관적 락 | 완주 지급과 아이템 구매가 겹치면 한쪽 잔액 갱신이 사라진다 | `findByChildIdForUpdate` |
| 지급 멱등 | 같은 세션에 두 번 지급되면 별가루가 무한정 늘어난다. 세션 단위와 장면 단위 인덱스를 갈라 장면 보너스 2건째가 막히지 않게 했다 | `stardust_transactions` 부분 유니크 인덱스 |
| 인덱스 | 대화 내역과 이어하기가 세션당 수십 건을 매번 훑는다 | `messages(session_id, turn_order)` 등 |
| N+1 방어 | 홈 한 번에 세션, 이야기, 주제, 지갑, 행성이 엮여 조회가 폭발하기 쉽다 | `open-in-view: false`, `batch_fetch_size: 100` |
| 401과 403 분리 | 만료된 토큰이 권한 없음으로 보이면 클라이언트가 재로그인 시점을 못 알아챈다 | `RestAuthenticationEntryPoint`, `RestAccessDeniedHandler` |
| Actuator 최소 노출 | 운영 정보가 인증 없이 새어 나가지 않는다 | `management.endpoints.web.exposure.include: health` |

## 4. 착수 순서

**1단계. 설정 묶음 (합쳐서 2~3시간)**

1번부터 10번까지다. 대부분 설정 몇 줄이라 직접 하나 AI를 쓰나 시간이 같고, 안 하면
실사용에서 곧바로 드러나는 것들이 여기 다 있다. 여기부터 한다.

**2단계. 메일을 먼저 건다**

12번은 유일하게 AI로 줄지 않는 반나절짜리다. 코드보다 발신 도메인 인증과 스팸함 확인이
시간을 먹는다. 13, 14, 15, 19가 여기 걸려 있으므로 **먼저 신청해 두고 다른 것을 한다.**

**3단계. 보안 묶음**

11번을 먼저 하고 15, 16, 17을 잇는다. 순서가 중요하다. 브루트포스 방어를 넣으면서
로그아웃이 실제로는 세션을 못 끊는 상태면 앞뒤가 맞지 않는다.

**4단계. 나머지**

18번과 19번은 대화 턴 파이프라인과 벤더 선정에 걸려 있어 그쪽 진행에 맞춘다.
20번부터 25번은 정해진 자리에 정해진 코드를 넣는 일이라 AI로 가장 크게 줄어든다.

전부 직접 하면 약 6일, AI를 쓰면 약 3일이다. 절반은 줄지만 나머지 절반은 어떻게 해도
줄지 않는다. 결정, 외부 계정 설정, 실제로 되는지 확인이 그것이다.

---

## 5. 두 가지 주의

**19번은 성격이 다르다.** 나머지가 있으면 좋은 것이라면 이것은 아동 대상 서비스가
안 하면 곤란한 축이다. 감지하려고 컬럼까지 만들어 두고 비워 두면, 몰라서 안 한 것이
아니라 알고도 안 한 것이 된다.

**15번은 역효과를 조심한다.** 계정 단위로 24시간 잠그면 남의 이메일로 10번 틀리는
것만으로 그 보호자가 하루 못 들어온다. IP와 계정을 함께 세고, 잠금은 짧게 두고,
잠겼다는 사실을 본인에게 알려 스스로 풀 수 있게 한다.
