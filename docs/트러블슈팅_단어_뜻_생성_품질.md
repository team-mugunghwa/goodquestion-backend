# 트러블슈팅: 단어 뜻 생성이 길이 규칙을 안 지키고, 실재 낱말을 거절하는 문제

- 발견: 2026-08-16, 실서버(Railway) 측정
- 상태: 해결 (프롬프트 보강 후 재측정 기준 충족, 5절)
- 관련 코드: `WordMeaningPromptBuilder`, `WordMeaningLlmClient`, `WordbookService.explain`
- 회귀 테스트: `WordMeaningPromptBuilderTest` (프롬프트 지시 고정 3건)

---

## 1. 증상

배포 서버에서 사전에 없는 낱말 11개를 담아 생성 결과를 측정했다.

| 증상 | 측정값 |
|---|---|
| 뜻 길이 20자 초과 | **11건 중 7건**(64%), 최대 36자 |
| 실재 낱말 오거절(422 `INVALID_WORD`) | "아궁이" 1회 거절 -> 재시도 시 정상 저장 |

초과 사례:

```
36자  부뚜막  부엌에서 음식을 데우거나 놓는 높은 돌이나 판을 가리키는 말이에요
33자  다듬이  천이나 옷감을 두드려서 매끈하게 해 주는 도구나 손길이에요.
30자  아궁이  옛날에 집 안 부엌에 불을 지펴 음식을 하던 곳이에요.
25자  가마솥  크고 둥근 무쇠나 흙으로 만든 오래된 냄비예요
```

## 2. 왜 문제인가

**길이**: 화면이 깨지지는 않는다. 다만 검수된 사전 뜻(15자 안팎)과 생성 뜻(30자대)이
단어장에 나란히 놓여 품질 편차가 그대로 보인다. 20자 규칙을 둔 이유(저학년 텍스트
밀도)가 그 단어들에서만 무너진다.

**오거절**: 이쪽이 더 무겁다. 관문(`INVALID_WORD`)은 STT 오인식이 만든 존재하지 않는
말을 막으려고 둔 것인데, 반대로 **아이가 진짜 궁금해한 낱말을 "담기 어려운 말이에요"로
막아 버린다.** 기능이 안 되는 실질 장애다. 우리 이야기가 옛날 배경이라 고어/생활어가
많이 나오는데 판정이 그쪽에 취약하다.

## 3. 원인

**길이 - 모델은 글자를 못 센다.** "20자 이하로 쓴다"는 지시는 모델이 검증할 수 없는
제약이다. 자연스러운 뜻풀이를 쓰면 한국어에서는 25~35자가 쉽게 나오고, 모델은 그것이
규칙 위반인지 알지 못한다. 규칙을 글로 적어 두는 것만으로는 안 지켜진다.

**오거절 - 판정이 흔들린다.** `isRealWord`는 뜻 생성과 같은 호출에서 나오는 모델 판단이라
호출마다 결과가 다를 수 있다. 같은 "아궁이"가 한 번은 false, 곧바로 재시도하면 true였다.
기존 지시("오타나 음성 인식 오류로 보이는 존재하지 않는 말이면 false")는 **애매할 때
어느 쪽으로 기울지를 정해 주지 않아서**, 낯선 옛말이 false로 떨어질 여지를 남겼다.

**곁가지**: 프롬프트 안의 JSON 예시가 예문 3종 확장(V14) 때 갱신되지 않아 옛 필드명
(`exampleSentence`)을 그대로 담고 있었다. 실제 출력 스키마와 어긋난 상태였다.

## 4. 대응

### 4-1. 길이 - 지시 대신 예시를 준다

세는 규칙 대신 **짧은 뜻 예시 3개**를 프롬프트에 넣었다. 검수된 시드 문구를 그대로 쓴다.

```
기왓장 -> 지붕을 덮는 납작한 조각이에요   (15자)
두레박 -> 우물에서 물을 뜨는 그릇이에요   (15자)
이장   -> 마을 일을 돌보는 사람이에요     (14자)
```

길이를 늘리는 실제 패턴도 이름 붙여 금지했다 - 재료 설명("무쇠나 흙으로 만든"),
시대 설명("옛날에"), 용도 나열("데우거나 놓는"). 측정에서 관찰된 것들이다.

마침표 금지도 함께 넣었다. 생성 뜻 일부만 마침표로 끝나 시드와 섞이면 화면에서
들쭉날쭉해 보인다.

### 4-2. 오거절 - 애매하면 통과로 기운다

판정 기준을 한쪽으로 못 박았다.

> isRealWord는 **확실히 존재하지 않는 말일 때만** false다. 낯설거나, 옛말이거나,
> 사투리이거나, 잘 안 쓰는 말이어도 실제로 쓰이는 낱말이면 true다. 판단이 애매하면
> true로 답한다. false는 자음/모음이 뭉개진 소리 조각처럼 어느 낱말로도 읽히지
> 않을 때만 쓴다.

**의도적으로 관문을 느슨하게 만든 것이다.** 관문이 놓치는 오인식 단어는 아이가 확인
줄에서 단어를 보고 담기를 누르는 구조가 한 번 더 거른다. 반대로 관문이 실재 낱말을
막으면 아이에게는 그냥 고장이라 되돌릴 방법이 없다. 두 오류의 무게가 다르다.

## 5. 재측정 결과 (2026-08-16, 대응 배포 후)

같은 낱말 11개로 다시 쟀다. 기준(초과 2건 이하, 오거절 0건)을 충족한다.

| | 대응 전 | 대응 후 |
|---|---|---|
| 20자 초과 | 7건 / 11 | **1건 / 11** |
| 최대 길이 | 36자 | **22자** |
| 실재 낱말 오거절 | 1건("아궁이") | **0건** |
| 마침표 섞임 | 3건 | **0건** |

같은 낱말의 변화가 뚜렷하다.

```
아궁이  30자 -> 16자   불을 지피는 구멍이나 장소예요
부뚜막  36자 -> 15자   부엌 한가운데 있는 난로예요
다듬이  33자 -> 15자   옷감을 두들겨 펴는 도구예요
가마솥  25자 -> 22자   둥글고 큰 솥으로 음식을 끓이는 도구예요   (유일한 초과)
```

**주의 - 짧아진 대신 정확도가 조금 떨어진 사례가 있다.** "부뚜막 -> 부엌 한가운데
있는 난로예요"는 15자로 줄었지만 부뚜막을 난로라고 한 것은 엄밀하지 않다. 길이를
조이면 설명을 덜어내므로 이 방향의 손실이 따라온다. 검수된 어휘 사전이 채워질수록
이 경로 자체가 줄어드는 것이 근본 해법이라는 점(6절)이 여기서도 확인된다.

## 6. 한계

- **프롬프트 대응은 보장이 아니다.** 확률을 낮출 뿐 0으로 만들지 못한다. 서버가 길이를
  강제하려면 자르기(문장 훼손) 또는 재생성(호출 2배)뿐이라 지금은 쓰지 않는다.
- 검수된 이야기 어휘 사전이 채워질수록 이 경로 자체가 줄어든다. 근본 대응은 사전 확충이다.
- 재측정이 필요하다. 아래 방법으로 같은 수치를 다시 재서 이 문서에 갱신한다.

## 7. 재측정 방법

배포 서버에 사전에 없는 실제 낱말을 담고 뜻 길이를 잰다(측정 후 삭제).

```bash
B=https://goodquestion-backend-production.up.railway.app
# TOKEN=로그인 액세스 토큰, CHILD=아이 id, SCENE=장면 id
for W in 아궁이 두레박 가마솥 부뚜막 초가집 지게 멍석 담벼락 우물 절구 다듬이; do
  curl -s -X POST "$B/api/children/$CHILD/words" \
    -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
    -d "{\"word\":\"$W\",\"entryType\":\"UNKNOWN\",\"sourceSceneId\":\"$SCENE\"}" \
  | python3 -c "
import sys,json
d=json.load(sys.stdin)
if 'meaning' not in d: print('거절', d.get('code')); raise SystemExit
m=d['meaning']; print(('OK ' if len(m)<=20 else '초과'), len(m), m, d['id'])"
done
```

기준: 20자 초과가 11건 중 2건 이하, 오거절 0건.

## 8. 교훈

- **모델이 검증할 수 없는 제약은 지시로 걸지 않는다.** 글자 수, 개수, 순서 같은 것은
  예시로 보여 주거나 서버가 검증해야 한다.
- **관문을 만들 때 두 방향 오류의 무게를 먼저 정한다.** 놓치는 쪽과 막는 쪽 중 무엇이
  더 나쁜지에 따라 애매한 경우의 기본값이 갈린다. 여기서는 "막는 쪽"이 더 나빠서
  통과로 기울였다.
- **프롬프트 안의 스키마 예시는 실제 스키마와 함께 갱신한다.** 둘이 어긋나면 모델이
  옛 필드명으로 답할 수 있다. 테스트로 고정해 두면 다음 확장 때 자동으로 걸린다.
