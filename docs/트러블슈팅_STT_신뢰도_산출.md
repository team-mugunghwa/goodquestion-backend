# 트러블슈팅: 신뢰도를 주지 않는 STT에서 저신뢰 발화 걸러내기

오인식된 아이 발화를 걸러낼 신뢰도 파이프라인이 설계만 있고 동작하지 않던 문제다.
벤더(gpt-4o-mini-transcribe)가 신뢰도를 직접 주지 않는다는 것이 원인의 절반,
기준값이 미정이라 판정 코드가 비어 있던 것이 나머지 절반이었다. 토큰 logprob을
서버가 집계해 신뢰도를 만들고 기준값 0.5를 확정해서, 항상 false였던 저신뢰 표시가
실측 신뢰도 기반으로 동작하게 됐다.

- 상태: 해결 (기준값은 아동 실녹음 검증 후 보정 예정)
- 관련 코드: `OpenAiSttClient`, `SttConfidencePolicy`, `SpeechService`, `MessageService`
- 회귀 테스트: `SttConfidenceAggregationTest`, `SttConfidencePolicyTest`, `SpeechSmokeTest`

---

## 1. 증상

**저신뢰 발화를 거르는 장치가 전부 만들어져 있는데 하나도 동작하지 않는다.**

- `messages.stt_confidence` 컬럼: 항상 null
- `messages.stt_low_confidence` 컬럼: 항상 false (하드코딩)
- 리포트 대표 발화의 저신뢰 제외 필터: 걸러내는 것이 없음
- "잘 못 알아들었을 수 있어요" 다시 말하기 안내: 띄울 근거가 없음

문제의 성격이 특이하다. 코드가 틀린 게 아니라 파이프라인의 양끝(DB 컬럼, 요청 필드,
응답 플래그, 리포트 필터)만 있고 가운데(신뢰도를 만드는 곳, 판정하는 곳)가 빈 채로
남아 있었다. 설계 당시 "기준값 미정"으로 보류한 것이 그대로 굳은 상태였다.

왜 문제인가. 아동 음성 인식은 성인보다 크게 부정확하다. 실측에서도 "방귀를 뀌어서"가
"방비를 끼어서"로 인식됐다. 오인식된 발화가 그대로 흘러가면 두 곳에서 사고가 난다.
하나는 보호자 리포트다 - 대표 발화는 보호자에게 "아이가 이렇게 말했다"고 보여주는
자리인데, 아이가 하지 않은 말이 실릴 수 있다. 다른 하나는 아이 경험이다 - 인식이
엉망인 채로 대화가 진행되면 캐릭터가 동문서답을 한다.

## 2. 원인

### 벤더가 신뢰도를 주지 않는다

whisper-1은 verbose_json 형식에서 세그먼트별 요약 통계를 준다. avg_logprob(평균
로그확률), no_speech_prob(무음 확률), compression_ratio(반복 감지)로, 저신뢰 판정에
바로 쓸 수 있는 값들이다.

gpt-4o-mini-transcribe는 이것이 전부 없다. 지원하는 응답 형식이 json뿐이고, 기본
응답은 `{ "text": "..." }` 한 필드다. 신뢰도라고 부를 만한 것을 아무것도 주지 않는다.

우리 구현도 text만 파싱하고 있었다. `/api/stt` 응답에 신뢰도 필드 자체가 없으니,
발화 제출 요청의 sttConfidence(클라이언트가 되올리는 구조)는 항상 비어서 왔다.

### 기준값이 미정이었다

설계 문서 전부가 "기준값 미정, 판정은 서버가"로 일치했고, 기획 문서 6종에는 STT
신뢰도라는 개념 자체가 없다. 정할 사람이 없어서가 아니라 정할 근거(벤더가 주는
신호의 형태, 아동 음성의 특성)가 정리되지 않아 미뤄진 것이다.

## 3. 분석

### 신뢰도를 만들 수 있는가

gpt-4o 계열 transcribe에 `include[]=logprobs` 파라미터를 주면(json 형식에서만 동작)
토큰별 `{ token, bytes, logprob }` 배열이 붙는다. 요약 통계는 없지만 원재료는 있다.

토큰 logprob에서 발화 신뢰도를 만드는 통용 방식은 **exp(logprob 평균)**, 즉 토큰
확률의 기하평균이다. 0~1로 떨어져서 우리 스키마(numeric(4,3), 0~1 check)와 그대로
맞는다. ASR 연구와 OpenAI 쿡북이 같은 집계를 쓴다.

### 기준값을 얼마로 할 것인가

공인된 컷은 없다. 참조점이 둘 있다.

- Whisper 오픈소스의 표준 실패 컷: avg_logprob -1.0, exp로 환산하면 약 0.37.
  "디코딩이 실패했다" 수준의 느슨한 기준이다.
- 품질 의심 수준: LLM logprob 일반론에서 0.5~0.9 사이를 용도별로 쓴다. 우리 데모
  시드를 만들 때의 가정(0.52는 낮음, 0.88 이상은 정상)은 0.6 부근을 가리켰다.

여기에 아동 변수가 있다. 아동 음성은 성인보다 오인식률이 크게 높다(아동 낭독체
WER 26~40% vs 성인 2% 미만, 유치원생은 84.6%까지). 인식이 어려우니 신뢰도 분포
자체가 낮게 깔리고, 성인 기준을 그대로 쓰면 정상 발화까지 낮음으로 찍는 오기각이
늘어난다. 아이 입장에서 오기각은 "제대로 말했는데 다시 말하라고 한다"이다. 대화
흐름이 끊기는 비용이 크므로 아동 대상 서비스는 기준을 느슨하게 잡으라는 것이
관련 연구들의 공통 방향이다.

그래서 실패 컷(0.37)과 품질 의심(0.6) 사이에서 아동 쪽으로 완화한 **0.5**로 확정했다.
어차피 절대값은 실측 없이 정당화되지 않으므로(토큰 logprob 신뢰도는 과신 경향이
있다는 것이 문헌의 공통 지적) 설정값으로 빼서 아동 실녹음 검증(미결-01) 후 보정한다.

### 판정 결과를 어디에 쓸 것인가

설계 문서가 이미 정해 둔 두 곳 그대로다.

1. **다시 말하기 안내 (비차단)**: 안내가 의미 있는 유일한 시점은 아이가 변환 텍스트를
   확인하고 제출하기 **전**이다. 그래서 판정을 `/api/stt` 응답에 실었다. 제출 후에
   알려주는 것은 이미 늦다 - 턴이 처리되고 캐릭터가 대답한 뒤다.
2. **리포트 대표 발화 제외**: 저장된 발화의 `stt_low_confidence`로 필터링한다.

분석(LLM) 제외에는 쓰지 않는다. 발화 품질의 분석 단계 처리는 분석 모델의
utteranceValidity(SHORT/UNCLEAR)와 캐릭터 유도가 담당한다는 것이 주최 측 문서의
설계라서, STT 신뢰도가 그 영역을 침범하면 같은 문제를 두 기준이 다투게 된다.

## 4. 적용한 것

### 4-1. logprobs 요청과 서버 집계 (완료)

`OpenAiSttClient`가 `response_format=json`과 `include[]=logprobs`를 요청하고,
토큰 logprob을 exp(평균)으로 집계해 소수점 3자리 신뢰도를 만든다. 반환형이
텍스트 하나에서 `SttResult(text, confidence)`로 바뀌었다.

### 4-2. 판정 단일 창구 (완료)

`SttConfidencePolicy` 하나가 판정한다. 기준값은 `external.stt.low-confidence-threshold`
설정(기본 0.5)이다. 판정 주체를 서버로 통일한 이유는 클라이언트마다 기준이 갈리면
리포트 필터링이 흔들리기 때문이다.

한 가지 원칙을 명시했다. **모름(null)과 낮음(0)은 다르다.** 벤더가 logprob을 안
주거나 형식이 바뀌어 신뢰도를 못 만들면 null이 되는데, 이것을 낮음으로 취급하면
멀쩡한 발화가 전부 리포트에서 사라진다. null은 걸러내지 않는다.

### 4-3. 제출 전 안내 경로 (완료)

`/api/stt` 응답이 `{ text, confidence, lowConfidence }`로 확장됐다. lowConfidence가
true면 프론트가 "잘 못 알아들었을 수 있어요. 다시 말해 볼까?"를 띄우되 차단하지
않는다 - 텍스트가 맞다면 아이는 그대로 보내도 된다. confidence는 발화 제출의
sttConfidence로 되올라와 저장된다.

### 4-4. 저장 시 판정 (완료)

`MessageService.appendChild`의 하드코딩 false를 서버 판정으로 바꿨다. 원값도 함께
저장하므로 기준값이 바뀌면 소급 판정할 수 있다.

## 5. 전후 비교

| 항목 | 전 | 후 |
| --- | --- | --- |
| **STT 응답** | **text 한 필드** | **text + 신뢰도 + 저신뢰 판정** |
| **stt_confidence 저장값** | **항상 null** | **실측 신뢰도 (왕복 스모크 0.999 확인)** |
| **stt_low_confidence** | **항상 false (하드코딩)** | **서버 판정 (기준값 0.5)** |
| 리포트 대표 발화 필터 | 있으나 무동작 | 동작 |
| 다시 말하기 안내 근거 | 없음 (빈 결과 422뿐) | 제출 전 lowConfidence 플래그 |
| 기준값 조정 | 코드 수정 | 설정값 (배포 없이 환경변수) |
| 신뢰도를 못 받은 발화 | - | 걸러내지 않음 (모름 != 낮음) |

확인 기준은 셋이다. `SttConfidenceAggregationTest`가 집계식을, `SttConfidencePolicyTest`가
경계(0.499 낮음 / 0.5 정상 / null 정상)를 고정하고, `SpeechSmokeTest`가 실호출에서
신뢰도 수신을 검증한다 - 벤더가 응답 형식을 바꾸면 여기서 걸린다.

## 6. 남은 것

### 아동 실녹음 캘리브레이션

0.5는 문헌 근거로 정한 출발값이지 실측값이 아니다. 스모크 테스트의 합성 성인
음성은 0.999가 나온다 - 깨끗한 입력이라 당연하고, 실제 아동 발화의 분포는 이보다
한참 낮게 깔릴 것이다. 아동 실녹음 검증(미결-01)에서 정상 발화와 오인식 발화의
신뢰도 분포를 재고 컷을 옮긴다. 설정값으로 빼 둔 이유다.

### 신뢰도 밖의 오인식

logprob은 "모델이 확신했는가"이지 "맞았는가"가 아니다. 모델이 확신하며 틀리는
경우(그럴듯한 다른 단어로 인식)는 신뢰도로 잡히지 않는다. 지금은 어휘 힌트
(vocabulary-hint)와 아이의 텍스트 확인 절차가 이 부분을 막고 있고, 무음 구간
환각(정형 문구, 반복 패턴) 감지 같은 보조 휴리스틱은 실사용 데이터가 쌓인 뒤
필요성을 판단한다.
